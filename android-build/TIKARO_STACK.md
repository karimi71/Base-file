# Tikaro offline dependency stack

This layer extends Base-file with the libraries and build/test tools that are
necessary for the planned Tikaro application while keeping them out of Tikaro's
APK unless its own Gradle configuration declares them.

## Compatibility baseline

- Gradle 8.9
- Android Gradle Plugin 8.7.3
- Kotlin and Kotlin serialization plugin 2.0.21
- KSP 2.0.21-1.0.28
- Compose BOM 2024.12.01 (Compose 1.7.6, Material3 1.3.1)
- compileSdk 35, Build Tools 34.0.0, compact JDK 17

`tikaro-stack-smoke-test/REQUESTED_COORDINATES.tsv` is the authoritative direct
coordinate list. `maven/BASE_FILE_COORDINATES.tsv` is the generated direct and
transitive repository inventory. Gradle lockfiles generated by the online audit
are committed beside each smoke project and are enforced again in a clean,
network-disabled Gradle user home.

## Included

- KSP plus the Kotlin serialization Gradle plugin
- Room runtime/KTX/compiler/testing and its selected SQLite graph
- Preferences DataStore and its selected Okio graph
- Coroutines 1.9.0 runtime, Android dispatcher, and test utilities
- Lifecycle, ViewModel, SavedState, Activity, and Core families needed by Tikaro
- Navigation Compose 2.8.9 and navigation testing
- Complete required Compose runtime/UI/foundation/animation/Material3 graph,
  debug tooling, Compose UI tests, and core Material icons
- WorkManager runtime/KTX/testing
- Glance, AppWidget, Material3, and Glance test artifacts
- stable Biometric, DocumentFile, ExifInterface, Startup, and Tracing
- kotlinx.serialization JSON 1.7.3
- AndroidX Test, Espresso, UI Automator, JUnit 4, Truth, and Turbine
- Macrobenchmark, Baseline Profile plugin, and ProfileInstaller
- Paparazzi 1.3.5 screenshot tests
- debug-only LeakCanary 2.14
- Detekt 1.23.7, Ktlint Gradle plugin 12.1.2 with pinned Ktlint CLI
  1.3.1, and Dependency Analysis plugin 2.2.0

## Deliberately not included in this Tikaro-essential layer

The following were explicitly optional, intended only for a universal catalog,
or require a demonstrated application need: SQLite bundled, Proto DataStore and
the protobuf plugin, biometric alpha APIs, Security Crypto, Tink, Moshi/Gson as
application JSON stacks, Coil, PDFBox, kotlinx-datetime, JUnit 5, MockK/Mockito,
material-icons-extended, WorkManager multiprocess, and network/telemetry/payment
SDKs. Core-library desugaring is also not enabled until Tikaro source actually
uses an API that requires it.

These can be added later as isolated, pinned layers without changing Tikaro's
runtime dependency graph.

## Smoke projects

- `tikaro-stack-smoke-test`: real Compose app using Room through KSP, Preferences
  DataStore, serialization, Navigation, WorkManager, Glance, biometric/framework
  integrations, JVM Flow tests, Android instrumentation tests, a benchmark
  module, and a static baseline profile packaged into release output.
- `paparazzi-smoke-test`: renders a real Compose hierarchy on the JVM without an
  emulator or Android Studio.
- `quality-smoke-test`: applies Detekt, Ktlint, and Dependency Analysis and
  resolves their pinned engines.

The smoke projects are verification fixtures only; none is copied into a
consumer APK. A consumer project selects dependencies normally from the local
Maven repository injected by `offline.init.gradle`.
